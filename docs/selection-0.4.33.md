# 0.4.33 划词兼容验证（2026-10-23）

状态：**测试版，未达到全部常见应用验收通过，未发布。** 公开版本仍为 0.4.32。此次检查包含 20 款已安装应用，验证深度各不相同；不能将下面的名单作为完整支持承诺。

## 已修复的缺口

1. QQ 7.0.2 将 Electron Framework 改名为 QQNT.framework，原来仅按目录名称检查会漏掉。现在同时检查框架 `CFBundleIdentifier=com.github.Electron.framework`，并按 PID、应用路径和启动时间缓存，避免每次划词扫描磁盘。
2. ChatGPT 新版、飞书、千问使用自定义 Chromium 框架，补充已有的 AXEnhancedUserInterface 激活与首次延迟重试。实际 Electron 版本仍优先使用 AXManualAccessibility。
3. 微信、ChatGPT、QQ、飞书、WPS、WPS 协作、豆包、千问读取不到选区时，在鼠标拖选／双击或明确的键盘选区手势后保留原有菜单。点击翻译或朗读后才尝试复制，随后恢复原剪贴板格式。
4. 命中控件、焦点控件及父级的查找限制为八层；保留取消、密码框、前台 PID、复制取词关闭、划词关闭、排除应用等限制。

未修改权限记录、签名身份、API Key 或语音模型。此处的修复不能归因于或替代系统授权修复。

## 已执行的检查

- 固定证书构建及 109 项核心检查通过。
- 98 项选区回归通过，包括长文本、Unicode、取消、保护控件、框架改名、应用策略和键盘选区。
- 微信与 ChatGPT 共 17 项生产菜单流程检查通过；QQ、飞书、WPS 协作、WPS、豆包、千问各 9 项同类检查通过。这些检查使用真实应用前台、生产鼠标手势处理函数及菜单，但手势由测试程序构造，不能当作实际聊天文本端到端验收。
- 独立自绘测试控件通过 11 项检查：原生菜单按钮点击、真实 Cmd-C、延迟 700ms 的长文本读取、文本及自定义二进制剪贴板恢复、复制关闭行为。使用专用测试剪贴板，通用剪贴板未改变。
- Chrome、Safari 的本地测试页各成功完整读取 99,000 字符中英文选区，逐字匹配（比较时仅归一化首尾空白）；直接 AX 路径不触发复制。

## 失败记录和边界

- 部分独立测试先后遭遇前台切换，出现菜单前或出现后目标应用失去焦点。其失败记录保留；之后在稳定前台下完成上述八款应用的菜单检查，不据此承诺全部场景稳定。
- 微信实际鼠标测试第一次复制未取得文本，第二次因窗口移动/焦点不可用而中止，未发送聊天消息，不能把小菜单出现当作真实消息取词通过。
- WPS 测试首轮正文读取成功，后续一次结果多 1 字符且未通过逐字比较，之后出现阻塞弹窗。已关闭本次测试明确识别的错误提示；其他窗口未作批量关闭。
- 自绘界面不提供真实选区时，仅能根据手势保留操作入口；这不能证明每次拖动都选中了文本，非文字拖动误出现菜单的边界仍需实操验收。
- 本轮不调用外部翻译 API、不发送聊天消息，验证的是选区、菜单和取词链路；翻译服务响应不包含在通过结论中。
- 密码框保护仅限系统能识别为安全控件的场景；不对完全不暴露语义的自绘密码控件作额外保证。

## 复测方式

构建后可运行 `Sonuvi.app/Contents/MacOS/Sonuvi --selection-test`。真实应用菜单检查使用 `--selection-compatibility-test`，默认检查微信与 ChatGPT，也可在其后传入一个或多个已运行应用的 Bundle ID。该检查会切换前台，须在桌面空闲、未锁屏时执行。复制集成检查使用 `--selection-copy-test`，需要先启动 `Tools/SelectionCopyFixture.swift` 编译的配套控件。

剩余验收需要：可用的登录后场景、尚未安装的客户端，以及不会同时移动窗口/切换前台的测试时段。优先补齐微信与 ChatGPT 的真实正文取词、WPS 重复长文档/PDF，再测试 QQ、飞书和其他国内客户端的正文。
