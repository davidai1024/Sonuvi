# Screenshot capture and in-place translation — 0.4.48

Screenshot Translation now defaults to a frozen result at the selected screen coordinates. Settings → Translate → Screenshot Results switches between Overlay in Place and the existing Translation Window.

After selecting an area, Sonuvi recognizes its text locally, groups compatible neighboring lines, and translates regions toward Chinese or English according to their source language. Only recognized text is sent to the configured DeepSeek model. Screen pixels and recognition coordinates stay on the Mac; no screenshots are saved by this flow.

The result toolbar switches Original/Translation, copies recognized source or completed translations, offers a split-menu action to copy a lossless PNG at the original pixel dimensions, opens the ordinary translation window, retries failed requests, and closes the result. Individual translated regions support native text selection and copying. Escape closes a focused result, and also closes it outside the app when existing Accessibility access permits a scoped global key monitor. Screen configuration and Space changes close stale results. Closing or starting a new capture cancels pending recognition and translation.

Capture uses a ScreenCaptureKit filter per display, explicit pixel dimensions from its points-to-pixels scale, `captureResolution = best`, and no JPEG encoding. Selection layers use each screen’s backing scale. A single-display crop preserves native pixels directly; cross-display selection composites at the greatest intersecting scale. Pixel-aligned result frames avoid fractional scaling. The oldest compatibility path is retained only below macOS 14; distributed app requirements remain macOS 14+.

Vision bounding boxes, not model-produced coordinates, determine text placement. Line grouping respects columns, spacing, approximate line heights and source-language direction. Requests batch up to eight compatible regions; exact markers preserve alignment and invalid markers fall back to individual requests. Individual long regions use resumable bounded fragments. Completed region results survive retries. Partial responses are visible, while the toolbar copies only validated completed regions. Native selection can still copy the currently visible text.

Text backgrounds use a dominant local screenshot color with a contrasting foreground. Fonts adapt to the source glyph height and available space. A short label may widen into nearby blank space, and a region may expand downward, stopping before other recognized text. It never shrinks below 9 pt; longer content scrolls locally and can be opened in a normal window. Translated-image copy is disabled for overflowing text so a clipped image is not presented as a complete translation; text copy remains available. This is a frozen screenshot overlay, not a live DOM replacement or image inpainting system. Complex photographic backgrounds and occluded/unrecognized text cannot be reconstructed perfectly.

Successful completion records one translation in local usage statistics, regardless of the number of OCR regions. Copy actions retain the existing local copy count.

Validation includes synthetic mixed-DPI/negative-origin crops, pixel alignment, bilingual OCR coordinates and line grouping, bounded layout, contrast, selectable views, marker alignment/fallback, resumable failures, cancellation, literal UI punctuation, and private-pasteboard copying. Native capture dimensions and interactive screenshot/overlay behavior are verified separately on the installed signed app. Other machines, display arrangements and OS versions require their own acceptance testing.
